# WPS Enhancer UI 设计规范

> 版本：v1.0  
> 用途：WPS Enhancer 后续所有 UI 页面、组件和交互实现的统一视觉基准  
> 当前载体：PC 桌面 App（Go + Wails）  
> 目标产品范围：WPS Word + WPS Excel

---

## 1. 设计依据

WPS Enhancer 的产品定位是：**针对 WPS Office 中 Word 和 Excel 的增强工具**。

当前项目资料中已经明确的实际功能只有：

- Excel 批量导入通讯录
- 支持选择源表格与模板
- 按列映射生成新表格
- 支持 xlsx / xls / csv / vcf / txt 导出
- 模板系统、列映射、预览和导出属于当前 Excel 功能体系
- 产品强调本地运行，不连接网络服务

因此，UI 设计不能把产品做成传统后台管理系统，也不能虚构尚未实现的 Word 功能。当前资料只把 Word 纳入产品目标范围，没有给出具体 Word 功能，因此 Word 页面必须保留统一视觉入口，但以“暂无已实现功能”的状态呈现。

这些内容均以当前项目资料为依据。fileciteturn1file16 fileciteturn1file17

---

## 2. 产品视觉定位

WPS Enhancer 是一个 **PC 端 Office 效率工具**，不是 SaaS 后台、内容网站或数据管理后台。

视觉目标：

> **轻量、专业、克制、直接、具有桌面工具感。**

用户打开应用的核心问题应该是：

> “我现在想增强 Word 还是 Excel？”

进入具体产品后：

> “我现在要使用哪个增强功能？”

进入具体功能后：

> “我现在应该完成哪一步？”

因此信息层级固定为：

```text
应用身份
  ↓
Word / Excel 产品切换
  ↓
当前产品的功能
  ↓
具体任务流程
```

不要设计成：

```text
Sidebar
  ↓
Dashboard
  ↓
统计卡片
  ↓
功能管理
```

后者会产生典型后台管理系统的视觉和交互感，与产品定位不一致。

## 3. 首页布局规范

### 3.1 顶部窗口区域

PC App 顶部只承担：

- WPS Enhancer 品牌识别
- Office 增强工具副标题
- 窗口控制
- 低频的帮助 / 设置入口

不使用网页式 Breadcrumb。

不使用：

- 首页
- 工作台
- Dashboard
- 用户中心
- 后台导航

左侧 Sidebar 默认不作为主导航结构。

---

### 3.2 Word / Excel 切换

Word 与 Excel 是产品的两个核心对象，因此使用顶部 Segment / Tab 进行切换。

默认状态：

**Excel 为第一项并默认选中。**

原因：

当前项目资料中只有 Excel 批量导入通讯录已经实现；Word 目前只是产品范围，没有明确已实现功能。

因此默认打开应用应该直接展示 Excel 已实现能力，让用户进入应用后立即看到可以使用的功能。

固定顺序：

```text
[ Excel ] [ Word ]
```

不得改成：

```text
[ Word ] [ Excel ]
```

除非产品功能状态发生实际变化。

---

## 4. Excel 页面规范

Excel 是当前 MVP 的实际功能入口。

当前核心功能：

**Excel 批量导入通讯录**

其视觉权重最高。

推荐结构：

```text
┌─────────────────────────────────────────────┐
│ 选择你要增强的 Office 工具                  │
│                                             │
│        [ Excel ] [ Word ]                   │
│                                             │
│ ┌──────────────────────┬─────────────────┐ │
│ │                      │ Excel 工具       │ │
│ │ 批量导入通讯录       │                 │ │
│ │                      │ 批量导入通讯录 › │ │
│ │ 选择文件 → 模板 →    │ 模板系统     › │ │
│ │ 列映射 → 预览 → 导出 │ 多格式导出   › │ │
│ │                      │                 │ │
│ │ [开始使用]            │                 │ │
│ └──────────────────────┴─────────────────┘ │
└─────────────────────────────────────────────┘
```

左侧是**主任务**，右侧是**当前产品下的辅助工具列表**。

不要把所有功能设计成完全相同大小的卡片。

原因：

当前 Excel 只有一个明确的已实现功能。主任务应该获得最高视觉权重，而模板、多格式导出等属于当前功能内部能力，不应该被包装成独立的“产品级功能”来制造虚假的功能数量。

---

## 5. Word 页面规范

当前资料没有提供任何已经实现的 Word 功能。

因此：

**禁止虚构 Word 功能名称、流程或具体能力。**

Word 页面只需要证明：

1. 产品支持 Word 方向；
2. Word 与 Excel 使用同一套设计体系；
3. 后续新增 Word 功能时不需要重新设计视觉语言。

Word 页面当前采用：

```text
Word
↓
Word 增强
↓
暂无已实现功能
```

视觉上使用 Word 专属识别色：

**#2563EB**

但不展示虚构的“Word 功能卡片”。

当未来加入 Word 功能后，直接复用 Excel 页面的结构：

```text
Word
↓
主功能
↓
辅助功能列表
↓
具体任务流程
```

## 6. 色彩系统

### 6.1 品牌主色

| Token | HEX | 用途 |
|---|---|---|
| Brand | `#E5484D` | 品牌、主按钮、当前操作、主要强调 |
| Brand Hover | `#D63B42` | 主按钮 Hover |
| Brand Soft | `#FFF1F2` | 品牌浅背景、选中辅助背景 |

品牌红属于 **WPS Enhancer 自身的品牌颜色**。

它不代表 Word，也不代表 Excel。

---

### 6.2 Office 产品色

| 产品 | 主色 | 浅背景 |
|---|---|---|
| Word | `#2563EB` | `#EFF6FF` |
| Excel | `#16A34A` | `#F0FDF4` |

规则：

- Word 图标使用 Word 蓝；
- Word 标签使用 Word 蓝；
- Word 状态辅助背景使用 Word 浅蓝；
- Excel 图标使用 Excel 绿；
- Excel 标签使用 Excel 绿；
- Excel 状态辅助背景使用 Excel 浅绿。

**不要用 Word 蓝替代品牌红。**

**不要用 Excel 绿替代品牌红。**

品牌色与产品识别色必须职责分离。

---

### 6.3 中性色

| Token | HEX | 用途 |
|---|---|---|
| Background | `#F6F6F7` | App 内容区域背景 |
| Surface | `#FFFFFF` | 卡片、面板、输入区域 |
| Surface Subtle | `#FAFAFA` | 次级背景 |
| Border | `#E5E7EB` | 普通边框 |
| Border Strong | `#D4D4D8` | 强边框 |
| Text | `#18181B` | 主文字 |
| Text Secondary | `#52525B` | 正文、重要辅助文字 |
| Text Tertiary | `#71717A` | 描述文字 |
| Text Muted | `#A1A1AA` | 次要信息、提示信息 |

禁止在单个页面随意新增相近灰色。

优先从上述 Token 中选择。

## 7. 字体规范

字体采用系统字体栈：

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei",
  sans-serif;
```

原因：

- macOS 使用系统字体；
- Windows 使用系统字体；
- 中文显示稳定；
- 不强制打包额外字体；
- 更符合 PC App 的原生感。

---

### 7.1 字号层级

| 层级 | 字号 | 字重 | 行高 | 用途 |
|---|---:|---:|---:|---|
| Page Title | 22px | 650 | 1.3 | 页面主标题 |
| Task Title | 20px | 650 | 1.3 | 核心功能标题 |
| Section Title | 13px | 650 | 1.4 | 区块标题 |
| Body | 12px | 400 | 1.75 | 普通描述 |
| Body Strong | 12px | 600 | 1.6 | 功能名称 |
| Secondary | 11px | 400 | 1.6 | 辅助信息 |
| Caption | 10px | 400 | 1.5 | 标签、状态、说明 |
| App Name | 13px | 650 | 1.4 | 顶部应用名称 |

不要为了“看起来大气”随意把桌面 App 的正文放大到 16px、18px。

这个产品强调工具效率，信息密度应该适中。

## 8. 按钮规范

### Primary Button

用途：

- 开始使用
- 下一步
- 导出
- 保存
- 确认

固定：

```text
背景：#E5484D
文字：#FFFFFF
字号：12px
字重：600
高度：36px
圆角：7px
```

### Secondary Button

用途：

- 取消
- 返回
- 辅助操作

固定：

```text
背景：#FFFFFF
文字：#52525B
边框：#E5E7EB
字号：12px
高度：33~36px
圆角：7px
```

不要让 Secondary Button 使用品牌红作为常态背景。

---

## 9. 卡片规范

卡片用于承载功能，不用于装饰。

固定原则：

- 背景：`#FFFFFF`
- 边框：`#E5E7EB`
- 圆角：10~12px
- 阴影：尽量弱
- 内边距：16~26px，根据内容级别决定
- 不使用大面积渐变
- 不使用强烈玻璃拟态
- 不使用夸张阴影

卡片的视觉重量应该来自：

**布局层级 > 内容层级 > 颜色 > 阴影**

而不是依赖大量装饰。

---

## 10. 间距规范

基础间距单位建议以 **4px** 为基础。

常用：

```text
4px
8px
12px
16px
20px
24px
32px
```

推荐：

- 图标与文字：8~12px
- 同组元素：8~12px
- 卡片内部：16~26px
- 区块之间：16~24px
- 页面主要区域：32~40px

不要出现大量随机间距，例如：

```text
13px
19px
27px
31px
```

除非是布局计算产生的结果。

---

## 11. 圆角规范

| 元素 | 圆角 |
|---|---:|
| App Window | 13px |
| Card | 10~12px |
| Button | 7px |
| Input | 7~8px |
| Small Badge | 6px |
| Icon Container | 8~10px |
| Tab | 7px |

整体风格是：

**轻圆角，而不是超大圆角。**

不要使用 16px、20px、24px 的大圆角让界面变成营销网站。

---

## 12. 图标规范

图标需要保持：

- 简洁
- 单色
- 线性或简单几何
- 16~20px 为主
- 与文字垂直居中

Office 产品识别图标：

```text
Word  → W
Excel → X
```

但真实开发中优先使用统一图标库或 SVG 图标。

禁止：

- 不同页面使用不同图标风格；
- 一部分使用 Emoji；
- 一部分使用彩色插画；
- 一部分使用线性图标。

---

## 13. 任务流程页面规范

当前 Excel 功能的实际流程是：

```text
选择源表格
↓
选择/创建模板
↓
列映射
↓
预览
↓
导出
```

项目资料明确包含模板、列映射、预览和多格式导出能力。fileciteturn1file17

因此功能页面使用**线性任务流**。

任务页面不要保留首页大量卡片。

进入任务后：

```text
功能名称
功能说明
↓
步骤指示器
↓
当前操作区域
↓
辅助说明
↓
取消 / 返回 / 下一步
```

核心原则：

> 首页解决“我要做什么”；任务页解决“我现在怎么做”。

统一使用：


```text

```

### Warning

## 16. 判断一个新页面是否跑偏

实现新页面前，检查以下问题：

### 产品层

- 这个页面是在帮助用户完成 Office 操作吗？
- 是否明确属于 Word 或 Excel？
- 是否使用正确的产品色？
- 是否存在没有产品依据的虚构功能？

### 布局层

- 是否仍然像一个桌面工具？
- 是否出现了不必要的 Sidebar？
- 是否出现了 Dashboard 式统计？
- 是否出现大量没有意义的卡片？
- 用户能否在最短路径找到主要操作？

### 视觉层

- 是否使用统一颜色 Token？
- 是否使用统一字号？
- 是否使用统一圆角？
- 是否使用统一间距？
- 是否出现新的未经定义的颜色？

只要其中任何一项明显偏离，就应该优先调整布局，而不是继续增加装饰。

## 17. 当前设计最终结构

当前 MVP 的首页结构固定为：

```text
PC App Window
│
├── App Title Bar
│
└── Content
    │
    ├── 页面标题
    │
    ├── [ Excel ] [ Word ]
    │
    ├── Excel
    │   ├── 主功能：批量导入通讯录
    │   └── 当前功能相关工具
    │
    ├── 最近使用
    └── 本地运行说明
```

Word 当前：

```text
PC App Window
│
└── Content
    │
    ├── [ Excel ] [ Word ]
    │
    ├── Word
    │   ├── Word 增强
    │   └── 暂无已实现功能
    │
    └── 保留与 Excel 一致的视觉结构
```

未来新增 Word 功能后，只增加实际存在的功能，不改变整体设计语言。

## 18. 最终原则

WPS Enhancer 的 UI 不追求“看起来功能很多”。

它追求：

> **用户打开应用后，立即知道自己能做什么，并且能够快速开始。**

因此：

**产品定位决定布局。**

**Office 类型决定产品色。**

**品牌决定主色。**

**任务流程决定功能页面。**

**Design Token 决定视觉一致性。**

以后新增任何页面，都应该是在这套规则之上扩展，而不是重新设计一套颜色、字体和布局。
