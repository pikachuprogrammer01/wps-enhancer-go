## 1. 激活码格式（客户端解析）

平台为 WPS 注册产品档案：`code_prefix = WPS-`，`verification_mode = online`，`signature_algorithm = rsa256`。

```
激活码 = WPS- + 分组5(base64(载荷JSON)) + '.' + 分组5(base64(签名))
例：WPS-xxxxx.yyyyy.zzzzz.wwwww.AAAAA.BBBBB...（每 5 字符一组，'.' 分隔载荷与签名）
```

| 规则 | 值 |
|------|----|
| 前缀 | `WPS-`（平台路由产品用，客户端可不校验但建议校验） |
| 编码 | **标准 base64**（字符集 A-Za-z0-9+/=；**不是 base64url**——base64url 的 `-` 与分组符冲突） |
| 分组 | `-` 每 5 字符一组（可读性）；解析时去除所有 `-` 分组符 |
| 分隔 | `.` 分隔载荷与签名（`.` 不在 base64 字符集中，无歧义） |
| 签名算法 | **RSA-2048 + SHA-256**（RSASSA-PKCS1-v1_5） |
| 签名长度 | 256 字节 → base64 344 字符（含填充） |

### 载荷字段（JSON，`payload_version = 1`）

```json
{
  "id": "uuid",              // 激活码唯一 ID（平台数据库主键）
  "version": 1,              // 载荷 schema 版本
  "type": "pro",             // 产品类型（激活仅接受 pro）
  "expiresAt": 1735689600000,// 过期时间戳（ms）
  "maxDevices": 1,           // 设备数限制（现恒为 1）
  "batchId": "batch-001",    // 签发批次
  "issuedAt": 1735689600000, // 签发时间戳（ms）
  "features": {},            // 功能集（可选，空对象亦可）
  "metadata": {}             // 扩展字段（可选，平台透传）
}
```

**V1 冻结语义**：字段只追加不删改；解析器按 `version` 分派，未知字段忽略。

## 2. 激活流程（在线验证）

```
本地验签（快速失败）→ 收集设备指纹 → POST /activate → 成功则本地持久化
```

### 2.1 本地验签（先行）

1. 去 `WPS-` 前缀与所有 `-` 分组符 → 按 `.` 分割 → 载荷 / 签名
2. 标准 base64 解码载荷 JSON（失败 → 激活码无效）
3. 用**内置公钥**验签（RSA-SHA256；失败 → 激活码无效）
4. 校验 `type === 'pro'`（trial 等类型暂不接受）

> 本地验签先行的意义：格式/签名错误的码**不发网络请求**，立即提示；同时为离线场景提供第一道防线（平台在线验证仍是最终裁决）。

### 2.2 在线验证

```
POST https://license.pikachu01.me/activate
Content-Type: application/json
请求体：{ "key": "<完整激活码>", "deviceFingerprint": "<设备指纹>" }
```

**响应（状态机五分支 + 非法码）**：

| HTTP | body.code | 含义 | 客户端动作 |
|------|-----------|------|-----------|
| 200 | —（body 含 `expiresAt`） | 激活成功（未绑定→记录绑定；已绑定且指纹匹配→恢复） | **持久化激活状态**，进入 Pro |
| 400 | `INVALID_KEY` | 格式/验签失败 | 提示「激活码无效」 |
| 403 | `REVOKED` | 已撤销 | 提示「激活码已被撤销，请联系开发者」 |
| 404 | `NOT_FOUND` | 验签通过但码不在库（数据回写前） | 提示「激活码无效，请确认后重试」 |
| 409 | `ALREADY_ACTIVATED` | 已绑定且**指纹不匹配**（一码一设备） | 提示「该激活码已绑定其他设备」 |
| 410 | `EXPIRED` | 过期（`expiresAt < now`） | 提示「激活码已过期，请联系开发者续费」 |

**超时与网络失败**：请求超时 3s；网络失败**不降级**——直接提示「网络不可用，请稍后重试」，不写入任何激活状态。

### 2.3 激活成功后本地持久化

本地保存（建议 App 数据目录内受保护文件，具体存储方案由 WPS 项目定）：

```json
{
  "key": "<完整激活码>",
  "payload": { ... 载荷原样 ... },
  "activatedAt": 1735689600000
}
```

**过期检查（每次启动）**：`payload.expiresAt < now` → 视为过期，锁定 Pro 功能，提示续费。
**状态判定**：有本地记录且未过期 → Pro；否则免费。

## 3. 设备指纹（桌面机器码）

**原则**：选择**稳定、跨重启/跨版本不变**的硬件/系统维度，SHA-256 后 hex/base64 作为 `deviceFingerprint`。

建议候选维度（具体组合由 WPS 项目在实现时定，需保证稳定）：

| 维度 | 稳定性 | 说明 |
|------|--------|------|
| 主板/系统序列号 | 高 | Windows: `wmic baseboard get serialnumber`；macOS: `ioreg` 等 |
| CPU 信息（型号） | 高 | 多机相同但组合后仍有效 |
| 磁盘序列号 | 高 | Windows: `wmic diskdrive get serialnumber` |
| MAC 地址 | 中 | 可能变化/虚拟网卡干扰 |
| 机器名/用户名 | 低 | **不要单独使用**（易变） |

> **容错约定**：平台存「当前指纹 + 指纹历史（最近 5 次）」，任一命中即视为同设备——指纹计算方式升级（如换了维度组合）后用户无需重新激活。因此指纹字符串**随版本升级可以变化**，只要生成规则稳定即可。

## 4. 解绑

```
POST https://license.pikachu01.me/deactivate
请求体：{ "key": "<完整激活码>", "deviceFingerprint": "<设备指纹>" }
```

| HTTP | body.code | 含义 | 客户端动作 |
|------|-----------|------|-----------|
| 200 | — | 解绑成功 | 清除本地激活状态，激活码可再次激活 |
| 403 | `FINGERPRINT_MISMATCH` | 指纹与绑定（含历史）不匹配 | 提示「解绑失败：设备信息不匹配」 |

**约束**：解绑属在线操作，离线不可用；平台侧有解绑频率限制（30 天 ≤ 2 次、冷却 7 天、终身 5 次），409/429 类响应按「稍后再试」提示。

## 5. 密钥（公钥）

- 平台为 WPS 生成独立 RSA-2048 密钥对；**私钥仅存平台**（Vercel env），**公钥内置 App**
- 公钥以 **PEM** 格式内置（打包为资源文件或常量字符串）；建议做轻量混淆（如 base64+反转）防静态提取，但 Python 无强混淆——**默认接受公钥可提取**（公钥本就公开，验签安全性不依赖公钥保密）
- **密钥轮换**：平台新增签发密钥后，新码用新密钥签——验签时平台按签发记录匹配公钥，**旧公钥继续可验**；客户端内置公钥只影响**本地预验签**。若客户端内置公钥过期（与平台新密钥不匹配），本地验签失败会误拒新码 → **平台换密钥时需同步发布新版本 App**（或客户端本地验签失败时降级为仅在线验证，由平台裁决——推荐后者，见 §2.1 备注）

> **推荐**：客户端本地验签失败时**不直接拒绝**，改发在线验证，以平台裁决为准（防止内置公钥过期导致新码被误拒）。本地验签只用于**快速失败**（格式错误/签名明显损坏）。

| 网络不可用/超时 | 「网络不可用，请稍后重试」 |
| 403 REVOKED | 「该激活码已被撤销，请联系开发者」 |
| 409 ALREADY_ACTIVATED | 「该激活码已绑定其他设备」 |
| 410 EXPIRED | 「该激活码已过期，请联系开发者续费」 |

## 7. Python 实现要点（原则，细节由 WPS 项目定）

- **RSA 验签**：`cryptography` 库（`load_pem_public_key` + `verify`，`padding.PKCS1v15` + `hashes.SHA256()`）
- **HTTP**：`requests` / `httpx`（3s 超时）；响应 JSON 解析
- **base64**：标准 base64（`base64.b64decode`），注意激活码内 `-` 为分组符需先去除、`.` 为分隔符
- **持久化**：平台不规定存储格式；建议与主配置分离、启动时校验完整性
- **⚠️ Python 防篡改能力弱**：用户可改代码跳过验签——**一码一设备/撤销的强制力在服务端**（激活时校验、绑定指纹）；本地逻辑只是体验层。这与浏览器扩展同理，属已接受的模型

## 8. 联调清单（平台上线后执行）

```
1. 平台注册 WPS 产品 → 签发测试码（CLI 或平台 /issue）
2. 测试码在未安装 App 的机器激活 → 200，App 进入 Pro
3. 同码换指纹激活 → 409 ALREADY_ACTIVATED
4. 解绑 → 200 → 原码再次激活 → 200（指纹匹配恢复）
5. 篡改 payload.expiresAt → 本地校验失效 → 过期锁定（410）
6. 撤销测试码 → 403 REVOKED
7. 断网激活 → 「网络不可用」提示，不写入激活状态
8. 重装 App（清本地数据）→ 同指纹重激活 → 200 恢复
```
